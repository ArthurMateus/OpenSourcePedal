## Done
- **Part 1, `dsp/112-fir-decimator` (base `main`), complete:** ADR-0005 Amendment A3. With the A2 halfband, the FIR stage-0
  decimator only stops at 0.56·fs, so HQ drive ASR was −51.5 dB at 1 kHz and −27.2 dB at 5 kHz/48k (IIR 8x: −91/−74).
  Stage 0 down is now a 293-tap full-band remez lowpass (pass to 20 kHz at 44.1k, stop from fs/2, 110 dB), folded
  taps + 8 partial sums (`dsp-core/src/oversampling/HalfbandFir.h` `FullbandDown`). `tools/design/halfband_fir.py`
  regenerates `HalfbandFirCoefs.h` (`--check` passes; needs scipy). FIR latency 101/116/124 at 2x/4x/8x, nulls
  −122…−125 dBFS, stage-0 down stopband −108.1 dB. `oversampler_fir_8x` budget: r0 1.29, maxCpuPercent 5.0.
  Verified: Release `/WX` (windows-msvc-ci) full suite, 195 test cases pass; clang-format 19.1.5 clean; guard clean.
  A Debug + RT-checker run was in progress at handoff (not confirmed).
- **Part 2, `dsp/112-drive-hq`, WIP (2 `wip:` commits):** `DriveRegion` uses `OversamplingFilter::fir` in HQ, pads
  `(factor − 2 % factor) % factor` samples (6 at 8x) at the oversampled rate after the slots, so HQ is an exact
  125-sample delay. A quality switch (prepare() with a different quality) keeps the output silent for the new latency,
  then ramps it in linearly over `kSwitchFadeMs` = 10 ms. Tests in `tests/dsp/test_drive_region.cpp`: integer latency
  (125) at every rate, bypass bit-exact in both modes, HQ disabled-region null ≤ −120 dBFS (−121…−122), rate × odd
  block matrix in both modes, HQ ASR ≤ IIR 8x and ≤ Live (HQ −92…−94 dB at 1 kHz, −74…−75 at 5 kHz), click-free
  switch (onset step = steady step), and an HQ fuzz with subnormal/huge input and NaN recovery after reset().
  `[driveregion]` passes in Release (10 test cases).
